# F2.6 – Persistência do Business Profile no Supabase

## Objetivo

Guardar o perfil comercial (WhatsApp Business) em `chat_contacts` para:
- **Cache:** exibir dados mesmo quando a Evolution estiver indisponível ou o contato não tiver perfil comercial “ao vivo”.
- **Histórico:** ter registro da última versão conhecida do perfil (descrição, site, horário, etc.).

## Desenho

### Modelo de dados

| Onde | O quê |
|------|--------|
| **Tabela** | `chat_contacts` (já existente) |
| **Coluna** | `business_profile JSONB` – objeto retornado pela Evolution (description, website, email, address, businessHours, etc.) |
| **Coluna** | `business_profile_fetched_at TIMESTAMPTZ` – data da última busca bem-sucedida (opcional; útil para “última atualização” e cache) |

Não foi criada tabela auxiliar para manter um único lugar de verdade por contato e reutilizar a mesma tabela que já tem perfil (nome, foto).

### Fluxo da API (GET business-profile)

1. Resolve conversa → contato e inbox (como hoje).
2. **Tenta** buscar na Evolution (`fetchBusinessProfile`).
3. **Se sucesso:**
   - Persiste em `chat_contacts`: `business_profile = payload`, `business_profile_fetched_at = now()`.
   - Responde `{ businessProfile, fromCache?: false }`.
4. **Se falha na Evolution** (502, timeout, etc.):
   - Se o contato tiver `business_profile` no Supabase, responde com esse valor e `fromCache: true`.
   - Caso contrário, responde o erro como hoje (ex.: 502).

Assim o front continua recebendo `businessProfile`; o campo opcional `fromCache` indica quando os dados vêm do cache.

### Quando persistir

- **Sob demanda:** apenas quando o usuário (ou o front) chama `GET /conversations/:id/contact/business-profile`. Não há job periódico na F2.6.

### Frontend

- Nenhuma mudança obrigatória: o contrato segue `{ businessProfile }` (e opcionalmente `fromCache`).
- Se quiser, o front pode exibir um indicador “Última atualização em …” usando `business_profile_fetched_at` quando/se a API passar esse dado no futuro (ex.: campo `fetchedAt` no JSON).

---

## Implementação

- Migration: `chat_contacts.business_profile` (JSONB), `chat_contacts.business_profile_fetched_at` (TIMESTAMPTZ).
- Endpoint GET business-profile: após fetch Evolution com sucesso → UPDATE em `chat_contacts`; em falha → leitura do cache (se existir) e resposta com `fromCache: true`.
